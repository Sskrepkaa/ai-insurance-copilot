# ПРОМПТ ДЛЯ АГЕНТА 3: AI Judge (проверка качества ответа)

Ты добавляешь модуль judge.py в backend/, который проверяет ответы агента на "groundedness"
(не выдумал ли агент факты, которых не было в данных инструментов).

## Задача
Создай judge.py с функцией:

```python
def judge_response(question: str, answer: str, tool_outputs: list[dict]) -> dict:
    """
    Использует отдельный вызов LLM (Groq, та же llama-3.3-70b-versatile) как судью.
    Судья получает: вопрос сотрудника, ответ агента, и все данные,
    которые вернули tools (get_claim_details, check_fraud_risk, get_customer_history).

    Промпт судье (адаптируй, но сохрани суть):

    "Ты - AI judge для контроля качества ответов страхового ассистента.
    Тебе даны: вопрос пользователя, финальный ответ агента, и фактические данные,
    которые агент получил из инструментов (tool_outputs).

    Проверь ДВА критерия и оцени каждый от 0.0 до 1.0:
    1. groundedness - содержит ли ответ ТОЛЬКО факты, присутствующие в tool_outputs,
       без выдуманных чисел/фактов, которых там не было
    2. relevance - отвечает ли текст на заданный вопрос

    Верни ТОЛЬКО валидный JSON без пояснений:
    {"groundedness": 0.0-1.0, "relevance": 0.0-1.0, "verdict": "pass"|"fail", "reason": "кратко почему"}

    verdict = "fail" если groundedness < 0.7 ИЛИ relevance < 0.7"

    Вопрос: {question}
    Ответ агента: {answer}
    Данные из tools: {tool_outputs}
    "

    Распарси JSON-ответ судьи (используй json.loads, обработай ошибку парсинга -
    если судья вернул невалидный JSON, верни {"groundedness": None, "verdict": "error"}).

    Возвращает dict с результатом.
    """
```

## Интеграция в main.py
В эндпоинте POST /chat, ПОСЛЕ того как получен финальный ответ агента:
1. Собери tool_outputs - список всех ToolMessage из истории графа за этот вызов
2. Вызови judge_response(question=message, answer=текст_ответа, tool_outputs=tool_outputs)
3. Добавь результат в response: {"type": "answer", "text": ..., "judge_score": {...}}

## Важно для обучения (это концептуально самая ценная часть проекта)
AI Judge - это ОТДЕЛЬНЫЙ вызов LLM, не тот же самый, что отвечал пользователю.
В реальных системах (как в вакансии VIG) judge иногда - более мощная/дорогая модель,
чем основной агент, потому что её задача - именно контроль, а не генерация.
Судья также может калиброваться против реальных оценок людей-экспертов -
это можно сделать позже: собрать 10-20 пар (ответ, оценка эксперта) и сравнить
с оценками judge, посмотреть на расхождения.

## Проверка
Вызови /chat с вопросом, где заведомо есть фактические данные (например про claim CLM-1001),
убедись что judge_score.groundedness близко к 1.0. Попробуй специально попросить агента
"придумай сумму, если не знаешь" - посмотри, упадёт ли groundedness score.
